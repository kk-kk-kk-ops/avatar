# 「会議モード」機能の実装メモ(2026-09-06〜08)

会議室(ミーティングエリア、kind: conference)専用のビデオ会議風UIを
`components/AvatarSpace.tsx`に追加した際の設計メモ。次にこの周辺を
触る人(人間・AIエージェント問わず)向けに、経緯と決定事項をまとめておく。

## 最重要ルール: スコープは常に「同じ会議室」のみ

この機能(常時表示プレビュー行・会議モードモーダル・画面共有の排他制御・
施錠アイコン)は、**自分が今いる会議室(conference kind)の中にいる人
だけ**を対象にする。「部屋にいる全員」でも「近くにいる人全般」でもない。
実装序盤でここを2回見誤り、都度ユーザーから訂正を受けた。

既存の`isIsolatedMeetingZone(zoneId)`(会議室/ミーティングエリアに
いる時は距離判定を無視し、同じゾーンかどうかだけで判定する)と
`eligiblePeerIds`(その判定を反映した近接リスト)をそのまま使えばよく、
新しい「全員」や「近く」の概念を作らないこと。

## 構成

- 常時表示プレビュー行: `selfInMeetingRoom`(=`isIsolatedMeetingZone`)が
  true の間だけ表示。210×140、ビデオOFFは黒背景+名前。順序は
  施錠アイコン→画面共有中の人→自分→他の人。会議室の外では、この機能を
  追加する前の挙動(通話/共有中の人がいる時だけ、160×120)に完全に戻る。
- 会議モードモーダル: `containerRef`内の`absolute inset-0 z-30`(サイドバー
  と同じ高さ・残り幅に自動で収まる)。画面共有が無い時は`ResizeObserver`
  (`meetingGridCallbackRef`)で実測したサイズから、4:3を保ったまま
  ちょうど収まるタイルサイズを算出する動的グリッド。共有中は上段に
  210×140の映像行+下段に画面共有(名前ラベル・拡大縮小・全画面ボタン付き)。
- 画面共有の排他制御: 同じ会議室内では常に1人まで。`screen-share-claim`
  broadcast(zoneId・claimedAt・peerId)を使い、受信側は自分の
  `meetingZoneId`が一致する時だけ反応、タイブレークは
  claimedAt→peerIdの決定的な比較。**会議室の外では一切送信されず、
  従来通り複数人が同時に共有できる。**
- 拡大縮小のスクロール: 拡大用コンテナに`flex items-center
  justify-center`+`overflow-auto`を使うと、はみ出した範囲の開始側
  (上・左)だけスクロールで届かなくなるCSSの既知の挙動がある。親の
  中央寄せをやめて子に`m-auto`を使う方式に統一済み(会議モードの画面
  共有エリア・全画面表示どちらも)。
- 全画面表示: `fixed inset-x-0 bottom-0 top-16`(ヘッダーは隠さない、
  ユーザー指定)。`expandedMedia.fromMeetingView`で、会議モードの
  「全画面」ボタンから開いた場合は閉じても購読を切らない
  (通常のプレビューから開いた場合は従来通り切る)。
- 施錠アイコン: 地図上の会議室ゾーンにあった元の施錠アイコンは削除した
  (常時表示プレビュー行・会議モードの両方に同じものを設置済みで、かつ
  z-index/DOM順の都合でプレビュー行と重なって見える不具合の原因
  だったため)。`handleLockIconClick`/`getConferenceZoneLocker`を
  共通利用。二重施錠のレースは、presence syncが
  `lockedMeetingZoneId`/`lockedMeetingZoneAt`を既知の相手に対して
  一切更新していなかった(名前等は更新されるのにこの2項目だけ抜けていた)
  のが原因の一つで、diffリストに追加+broadcastでの即時通知+800msの
  連打防止+自己修復effectで対応した。

## 現状のタイルサイズ

常時表示プレビュー行・会議モードの画面共有時の上段行はいずれも
**210×140固定**。画面共有が無い時のグリッドのみ、実測に基づく動的
サイズ(4:3維持)。実装途中で160×120→240×180→240×160→220×140→
210×140と何度も変わったので、コードを見ずに数値を信じないこと。

## 未検証・今後の注意点

- カメラ映像はsimulcast無効の固定160×120/150kbps(`node_modules/
  livekit-client`で確認済み)なので、表示サイズを変えても通信量は
  変わらない。画面共有はsimulcast(高画質/低画質)ありなので、表示
  サイズや自動配信の有無を変えると通信量が変わる点は今後も注意。
- この機能追加に伴うDBスキーマ変更は無し(すべてクライアント側の
  presence/broadcastで実装)。
- `deploy/livekit/LOAD_TEST_PLAN.md`の負荷試験前提は、対象範囲が
  「会議室のみ」に収まっている限り変わっていないはず(全員対象案は
  採用されなかったため)。
