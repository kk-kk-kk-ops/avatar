# LiveKit OSS移行・新機能 動作確認チェックリスト

`supabase/consolidated_setup.sql`を再実行し、環境変数(LIVEKIT_URL等)を
OSS側に切り替えた上で確認する。

## OSS基盤

- [ ] Cloud→OSS切替後、音声通話が問題なく繋がる
- [ ] ビデオ通話が問題なく繋がる(全プランで、日次上限内であれば利用可能)
- [ ] 画面共有の開始・選択視聴が問題なく動作する
- [ ] SSL/WSS接続が証明書エラーなく確立される
- [ ] TURN経由の接続(制限ネットワーク環境、モバイル回線など)が成功する
- [ ] Redis再起動後、LiveKitノードが自動的に復帰する
- [ ] 2台目ノードを追加した場合、新規ルームが自動的にいずれかのノードへ
      割り当てられ、同室の全員が同じノードで会話できる
- [ ] `lk load-test`実測(`LOAD_TEST_PLAN.md`)で、想定される最大同時利用時の
      帯域がWebARENA Indigoの安定運用目安(8GBプランで160GB/日)に対して
      どの程度の余裕があるかを確認済み

## 5プラン権限管理

- [ ] 無料/ライト/スタンダード/プロ/ビジネスの5プランが`/plan`に表示され、
      価格・人数上限の表示が仕様通り
- [ ] 各プランでミーティングルームの人数上限(5/10/15/30/50名)が適用され、
      超過時に「満員です」で入室できない
- [ ] 無料・ライトはビデオ通話・画面共有ともボタン付近に残り時間が表示される
- [ ] スタンダード以上は残り時間表示が出ず、無制限に利用できる

## 画面共有・ビデオ通話 日次利用時間制限(無料・ライトのみ)

- [ ] 無料(5分/5分)・ライト(60分/60分)で、プランごとの上限時間まで
      画面共有・ビデオ通話がそれぞれ独立して利用できる
      (画面共有を使い切ってもビデオ通話は別枠で利用できる)
- [ ] 残り時間がそれぞれのボタン付近に表示される
- [ ] 残り時間が0になると、利用中の場合は自動的に終了する
- [ ] 残り0の状態で新規に開始しようとするとエラーメッセージが出て開始できない
- [ ] JST 4:00をまたぐと利用可能時間が回復する
- [ ] 同一ユーザーが複数タブ/デバイスから使った場合も累積が正しく合算される
- [ ] スタンダード以上のプランでは、画面共有・ビデオ通話とも時間制限なく
      使い続けられる(daily_usageへの読み書きが発生しないことをネットワーク
      タブ等で確認できるとなお良い)

## 画面共有 選択視聴モデル

- [ ] 複数人が同時に画面共有していても一覧に全員表示される
- [ ] 視聴者は1人だけを選んでライブ視聴でき、他の共有者は静止画プレビューのまま
- [ ] 別の共有者に切り替えると、前の相手の購読が解除される(同時に2つライブ購読されない)
- [ ] 共有開始直後、選択前は最初の1フレームの静止画プレビューが表示される
- [ ] 選択中の相手が共有を終了すると、選択が自動的に解除される
- [ ] 選択中の映像をクリックすると全画面表示になる

## チャット(参加者ごとの1対1DM)

- [ ] 左サイドバーの参加者一覧で相手をクリックすると、その相手との
      スレッド(下半分のDMゾーン)に切り替わる
- [ ] 別の参加者に切り替えると、その相手との過去の履歴が表示される
      (スレッドが参加者ごとに分かれている)
- [ ] メッセージ送受信がリアルタイムに反映される
- [ ] リロード後も、同じ相手との直近の履歴(最大50件)が表示される
      (相手が別のブラウザセッションでも、認証ユーザーの安定IDで
      同一人物として履歴が引き継がれることを確認)
- [ ] 相手からメッセージが届くと、参加者一覧のその相手の行に未読マーク
      (色丸と名前の間の💬)が表示され、スレッドを開くと消える
- [ ] スマホ表示のハンバーガーボタンにも、未読があれば赤丸が表示される
- [ ] 自分宛てでないDM(他の参加者同士の会話)は表示されない
- [ ] 500文字を超える入力ができない
- [ ] 招待URL経由のviewOnly(既に自分のアカウントを持つ人が他人の招待URLを
      一時閲覧中)でも、通常アカウントと同様にDMの送受信・履歴表示ができる
- [ ] 投稿から1ヶ月経過したメッセージが自動削除される
      (`select public.delete_expired_chat_messages();`を手動実行し、
      作成日時を仮に過去へ書き換えたテスト行が消えることで即時確認可能)
- [ ] ルームを削除すると、そのルームのチャット履歴も即座に削除される
      (chat_messagesのon delete cascadeにより自動)

## β版1000人上限

- [ ] 入室中のユーザーが30秒おきに`online_sessions`を更新している
      (Supabaseのテーブルを直接確認)
- [ ] 同時接続数が1000人に達している状態で新規の無料プラン開始を試みると
      エラーメッセージが表示され、アカウントが作成されない
- [ ] 1000人を下回れば再度開始できる

## 負荷スコア監視

- [ ] `deploy/livekit/monitor/check-load-score.mjs`を手動実行し、
      マスター画面の負荷スコア表示と同じ値が出力される
- [ ] 閾値(300/600/900/1200)を試験的に超えさせ、Webhook通知が届く
- [ ] 同じ段階が続く間は再通知されない(スパムしない)
- [ ] `lk load-test`の実測結果と、閾値・重み付けに乖離が無いことを確認
      (乖離があれば`LOAD_TEST_PLAN.md`の手順で調整)

## 動画品質

- [ ] ビデオ通話が160×120/150kbps/15fps相当の低画質で送信されていることを
      ブラウザの開発者ツール(WebRTC internals)で確認
- [ ] 画面共有は圧縮されておらず、文字が読める画質を維持していることを確認
